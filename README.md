# 업데이트 v2 — GitHub에서 교체할 파일

기존 저장소의 **index.html, style.css, app.js 세 파일을 모두 교체**하세요. README.md는 안내 문서이므로 선택 사항입니다. 파일 이름과 위치는 그대로 유지합니다.

1. 새 ZIP을 내려받아 압축을 풉니다.
2. 기존 GitHub 저장소 최상위에서 Add file → Upload files를 선택합니다.
3. 새 index.html, style.css, app.js를 함께 올리고 Commit changes를 누릅니다. 새 저장소를 만들거나 Pages 설정을 바꿀 필요는 없습니다.
4. Actions에서 Pages 배포 완료를 확인한 뒤 기존 사이트 주소를 새로고침합니다. HTML에 버전 쿼리를 넣어 새 CSS/JS를 불러오도록 했습니다. 화면이 그대로라면 탭을 닫고 다시 열어 주세요.
5. 새로고침하면 이전 탭의 데이터와 모델은 사라집니다.

## 바뀐 사용법

- 카메라 바로 아래 **동작 수집 / 실시간 예측** 탭으로 전환합니다.
- 수집 탭의 이름 입력칸에서 두 동작 이름을 직접 지정합니다. 서로 다른 이름을 사용하세요. 이름 변경은 기존 좌표나 모델을 바꾸지 않습니다. 실제 동작을 바꾼다면 초기화 후 다시 수집하세요.
- **각 동작 목표**는 5·10·20 버튼 또는 1~100 사이 정수로 설정합니다. 표시된 실제 수집 횟수는 자동으로 셉니다. 목표에 도달해도 추가 수집할 수 있습니다.
- 학습 버튼은 두 동작 모두 목표 이상 수집하면 켜집니다. 학습에는 목표 수만큼 잘라 쓰는 것이 아니라 수집한 데이터 전체를 사용합니다.
- 5회씩 수집 → 학습 → 새 동작 테스트 → 목표를 10회로 변경 → 5회씩 추가 → 재학습하는 방식으로 비교하세요. 재학습은 전체 데이터로 새 모델을 만드는 방식입니다.
- 추가 수집 중에는 이전 모델을 유지합니다. 현재 모델이 실제로 학습한 동작별 횟수와 추가 데이터 미반영 안내가 표시됩니다. 재학습이 끝나면 새 횟수로 갱신합니다.
- 학습 완료 시 예측 탭과 카메라 위치로 이동합니다. **실시간 예측 시작**은 직접 누릅니다. 예측 이름과 확률은 카메라 위에도 표시됩니다.
- 수집 탭으로 돌아가면 예측이 중지됩니다. 초기화는 좌표와 모델을 지우지만 이름과 목표 설정은 유지합니다.
- 데이터가 많아져도 정확도나 확률 상승을 보장하지 않습니다. 매 단계 새 동작을 각 10회씩 시험해 정답 횟수를 비교하세요. 최소 1회 학습은 동작 확인용이며 신뢰할 만한 평가에는 부족합니다.

# 손동작 시간축 실험실 — 교사 첫 테스트

빌드·API 키·유료 서버 없이 동작하는 정적 웹앱입니다. `index.html`, `style.css`, `app.js`를 같은 폴더에 두세요. 파일을 직접 여는 대신 GitHub Pages의 HTTPS 주소로 접속합니다.

## 1. GitHub Pages 배포 (스마트폰에서도 가능)

1. GitHub에 로그인하고 새 **Public** 저장소를 만드세요. 예: `hand-motion-lab`. README 생성 옵션을 켜면 첫 화면에서 파일 추가가 편합니다.
2. ZIP을 내려받아 파일 앱에서 압축을 풉니다.
3. 저장소의 **Add file → Upload files**에서 `index.html`, `style.css`, `app.js` 세 파일을 업로드하고 **Commit changes**를 누릅니다. 메뉴가 안 보이면 브라우저의 ‘데스크탑 웹사이트 요청’을 켭니다. 업로드가 불편하면 **Create new file**로 같은 이름의 파일을 만들고 각각 코드를 붙여 넣어도 됩니다.
4. 세 파일이 저장소 최상위에 있는지 확인하세요. `hand-motion-lab/index.html`처럼 하위 폴더에 넣지 않습니다.
5. **Settings → Pages → Build and deployment → Source: Deploy from a branch**를 선택합니다.
6. **Branch: main**, 폴더 **/(root)**를 선택하고 **Save**합니다.
7. 배포가 끝나면 Pages에 표시되는 HTTPS 주소를 엽니다. 보통 `https://사용자명.github.io/hand-motion-lab/`입니다. Actions에서 배포 성공 여부도 확인할 수 있습니다.

GitHub 계정에 연결하거나 실제 배포한 상태는 아닙니다. 위 절차로 직접 업로드하세요. 무료 계정은 공개 저장소로 시작하면 됩니다. 공개되는 것은 코드이며 촬영 영상이나 학습 좌표는 저장소로 보내지지 않습니다.

## 2. 아이폰 / 안드로이드 첫 실행

- 아이폰: 배포 주소를 **Safari**에서 직접 엽니다.
- 안드로이드: 배포 주소를 **Chrome**에서 직접 엽니다.
- 메신저 안의 브라우저보다 해당 브라우저 앱에서 여세요. 네트워크가 필요하며 처음에는 라이브러리와 손 검출 모델 다운로드로 시간이 걸립니다.
- 휴대폰을 고정하고 밝은 곳에서 같은 한 손을 사용하세요. 테스트 도중 회전하거나 기기 위치를 바꾸지 마세요.

1. **카메라 켜기 → 허용**. 화면에 손가락 관절 점 21개가 따라오는지 확인합니다.
2. **좌→우 1회 기록**을 누르고 3초 동안 손을 화면 왼쪽에 놓습니다. ‘기록 중’이 표시되면 약 1.5초 동안 화면 오른쪽으로 이동합니다. 손 전체를 화면 안에 유지합니다.
3. ‘저장 완료’ 뒤 시작 위치로 돌아옵니다. 버튼을 다시 눌러 **10회** 모읍니다. 돌아오는 동작은 기록에 넣지 마세요.
4. **위→아래**도 같은 방식으로 **10회** 모읍니다. 시작 위치와 속도를 조금씩 바꾸되 동작 방향은 유지합니다.
5. **모델 학습하기**를 누르고 60회 학습이 끝날 때까지 기다립니다. 진행률과 학습 데이터 정확도가 표시됩니다.
6. **실시간 예측 시작**을 누릅니다. 학습 때와 비슷한 속도로 새 동작을 보여 주세요. 최근 1.5초를 분석하므로 동작 끝 무렵의 확률을 봅니다.
7. 시작 위치로 돌아오는 동안에는 반대 동작이 섞입니다. 돌아온 뒤 1.5초 정도 멈추고 다음 동작을 시작하세요.

## 3. 교사용 확인표

각 기기에서 별도로 수집·학습합니다. 날짜, 기종, OS/브라우저 버전, 학습 시간과 결과를 적어 두세요.

| 확인 | 기대 결과 |
|---|---|
| 카메라 허용 | 전면 영상과 관절 점이 보임 |
| 권한 거부 | 권한 안내 표시, 허용 후 다시 시작 가능 |
| 좌→우 / 위→아래 각각 10회 | 카운트 증가, 이후 학습 버튼 활성화 |
| 기록 중 손을 화면 밖으로 빼기 | 해당 기록 저장 안 됨 |
| 학습 | 진행률 상승, 완료 후 예측 버튼 활성화 |
| 새로운 좌→우 10회 | 동작 끝의 정답 횟수 기록: __ / 10 |
| 새로운 위→아래 10회 | 동작 끝의 정답 횟수 기록: __ / 10 |
| 정지 / 손 없음 | 움직임 대기 / 손 없음, 확률 초기화 |
| 다른 앱으로 이동 | 카메라 종료, 복귀 후 다시 켤 수 있음 |
| 데이터 추가 | 이전 모델 유지, 추가 데이터 미반영 표시, 재학습 후 횟수 갱신 |
| 새로고침 | 수집 데이터와 학습 모델 사라짐 |

학습 화면의 정확도는 이미 학습에 쓴 데이터에 대한 수치입니다. 검증 데이터 정확도가 아니므로, 위의 새 동작 20회 결과를 따로 보세요. 이 버전은 동작 경계를 자동 검출하지 않으며 다른 동작·반대 방향을 거부하도록 학습하지도 않습니다. 정지 상태는 간단한 이동량 기준으로 걸러냅니다. 두 클래스 확률의 합이 100%라는 사실이 실제 정답 보장을 의미하지 않습니다.

## 4. 코드가 하는 일

- MediaPipe Tasks Vision `0.10.32`: `FilesetResolver.forVisionTasks`, `HandLandmarker.createFromOptions`, `runningMode: 'VIDEO'`, `detectForVideo(video, timestamp)` 사용. JS와 WASM 버전을 동일하게 고정했습니다.
- TensorFlow.js `4.22.0`: 브라우저에서 `tf.sequential`, `tf.layers.dense`, `model.fit`, `model.predict` 사용.
- 카메라는 최대 약 15회/초 분석합니다. 검출 호출은 메인 스레드에서 실행되므로 저사양 폰에서는 화면 반응이 느려질 수 있습니다. GPU 초기화 실패 시 CPU로 재시도합니다.
- 기록은 1.5초간 손 21개 지점의 x/y/z와 시각을 수집합니다. 기록 시 손을 놓치거나 프레임 간격이 300ms를 넘으면 버립니다.
- 시각을 기준으로 선형 보간하여 **20 × 63 좌표**로 맞춥니다. 각 좌표에서 **첫 프레임의 같은 좌표**를 빼고 시간 순서대로 펼칩니다. 매 프레임 손목을 빼면 이동 경로가 사라지므로 그렇게 하지 않습니다.
- 모델: **1,260 입력 → Dense 12(ReLU, L2) → Dense 2(softmax)**, 학습 파라미터 15,158개. Adam, batch 8, epoch 60. LSTM은 아니지만 순서가 고정된 여러 시점의 변화량을 사용하므로 시간 정보를 학습합니다.
- 손목 이동 범위가 화면 정규화 좌표 기준 0.12 미만이면 정지로 간주합니다. 클래스 방향을 코드로 판정하는 규칙은 없으며 두 클래스 구분은 학습한 신경망이 수행합니다.
- 실시간 예측은 최근 1.5초의 슬라이딩 윈도를 최대 250ms마다 분석합니다.

## 5. 개인정보와 제한

앱은 영상 녹화, 사진 저장, 좌표 업로드, 분석 로그 전송 기능을 사용하지 않습니다. 영상은 카메라 미리보기와 손 검출에만 사용합니다. 좌표와 학습 모델은 탭 메모리에만 있습니다. 오디오 권한은 요청하지 않습니다.

웹페이지를 받는 GitHub와 라이브러리 제공 CDN(jsDelivr), 손 모델 제공 Google Storage에는 일반적인 다운로드 요청(IP 등 네트워크 정보)이 발생합니다. 따라서 ‘모든 네트워크 통신이 없음’을 의미하지는 않습니다. 수집한 영상/좌표를 전송하는 코드는 없습니다. 완전한 오프라인 버전은 이 범위에 포함하지 않았습니다.

## 6. 문제가 생기면

- 카메라가 안 열림: HTTPS Pages 주소인지 확인하고, 브라우저 사이트 권한에서 카메라를 허용합니다. 다른 앱에서 카메라를 사용 중이라면 종료 후 재시도합니다.
- 모델 다운로드 실패: 학교 Wi-Fi의 jsDelivr / Google Storage 차단 여부를 확인하거나 다른 네트워크에서 테스트합니다.
- 손 추적이 자주 끊김: 밝은 곳, 단순한 배경, 손 전체가 보이는 거리에서 천천히 움직입니다. 다른 앱을 닫습니다.
- 학습이 느림: 다른 탭을 닫고 기다립니다. 기기와 GPU 지원에 따라 차이가 있으며 완료 시간을 보장하지 않습니다.
- 예측이 한쪽으로 치우침: 초기화 후 같은 손·비슷한 속도로 두 클래스 데이터를 균형 있게 다시 수집합니다. 동작 뒤 되돌아오는 과정을 기록하지 마세요.
- 수정한 코드가 안 보임: Pages 배포 완료 후 새로고침합니다. 새로고침하면 기존 학습 데이터가 지워집니다.

## 검증 범위

JavaScript 문법, 화면 요소 연결, 타임스탬프 보간, 입력 특성 차원과 정지 판정 로직을 검사했습니다. 실제 CDN 로딩과 스마트폰 카메라·GPU 학습·예측의 종단간 검증은 수행하지 못했습니다. 위 기기별 확인표로 첫 현장 테스트를 진행해 주세요.
